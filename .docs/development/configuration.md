# Configuration reference
Implemented in [Settings](../../src/quotation_app/config.py). Explicit constructor values override environment variables, which override the root `.env`.

| Variable | Purpose |
|---|---|
| QUOTATION_DATABASE_URL | Required API runtime URL (`postgresql+psycopg`, explicit host and database) |
| QUOTATION_MIGRATION_DATABASE_URL | Owner URL, needed only for migrations, seed and API-key management; never used as a fallback |
| QUOTATION_WORKER_DATABASE_URL | Worker-role URL, needed only by `python -m quotation_app.worker`; never used as a fallback |
| QUOTATION_STORAGE_DIR | Attachment storage root (default `var/storage`, ignored by Git) |
| QUOTATION_MODEL | AI enquiry reader as `<provider>:<model>` (any LangChain chat model, e.g. `google_genai:gemini-3.5-flash-lite`). Unset = free offline rules, no AI (ADR 0017) |
| QUOTATION_MODEL_API_KEY | Secret API key for that provider; never commit it |
| QUOTATION_MODEL_OPTIONS | Optional JSON passed to the model as is, e.g. `{"timeout": 60, "max_retries": 2}` or `{"base_url": "..."}` |
| QUOTATION_AUTH_PROVIDER | Portal sign-in: `dev` (pick a synthetic member, no password) or `disabled`. Unset means `dev` in development/test and `disabled` in production; `dev` in production is rejected |
| QUOTATION_SESSION_HOURS | Portal session lifetime (default 8, max 24) |
| QUOTATION_SESSION_COOKIE_SECURE | Force the Secure cookie flag locally (always on in production) |
| QUOTATION_SIMULATED_CHANNEL_SECRET | Signs simulated manager-channel events. Unset disables the webhook and the simulated notifier; rejected in production. Generated by init_local_env.py |
| QUOTATION_SECRET_STORE | Where provider secrets live (D8): an entry point name in `quotation_app.secret_stores`. Unset = `local` in development/test, `none` in production (until a cloud store is chosen, D24); `local` in production is rejected |
| QUOTATION_SECRET_STORE_KEY | Key of the `local` store: 32 bytes, url-safe base64. Generated by `init_local_env.py --add-missing`; never commit it. Losing it makes stored provider secrets unreadable |
| QUOTATION_SECRET_STORE_OPTIONS | Optional JSON passed to the secret store as is (for cloud stores later) |
| QUOTATION_PUBLIC_BASE_URL | Public address of this API (e.g. a tunnel in development), only used to show webhook URLs |
| QUOTATION_PORTAL_DIST_DIR | Built React portal (e.g. `portal/dist`), served at `/portal/`; unset means it is not served |
| QUOTATION_ENVIRONMENT | `development` (default), `test` or `production`. Production rejects demo seeding, the dev login and the simulated channel |
| POSTGRES_PASSWORD | Compose bootstrap superuser password |
| POSTGRES_OWNER_PASSWORD / POSTGRES_APP_PASSWORD / POSTGRES_WORKER_PASSWORD | Compose passwords for quotation_owner, quotation_app and quotation_worker |
| TEST_DATABASE_URL / TEST_MIGRATION_DATABASE_URL / TEST_WORKER_DATABASE_URL | Integration-test URLs; each must name a `*_test` database |

Database URL representations and validation messages hide secret inputs. Do not log unwrapped secrets, or rendered Compose configuration that contains passwords.

[.env.example](../../.env.example) contains placeholders. The [local setup generator](../../scripts/init_local_env.py) creates the ignored `.env`, and `--add-missing` appends settings that an older `.env` lacks.

Connect, statement and pool-wait timeouts are 3 seconds, with a pool of 5 and no overflow. These are development defaults, not measured production settings.

**Fixed limits (code constants, not settings):**
- **Intake:** text up to 20,000 characters, up to 5 attachments of 5 MiB each and 15 MiB in total; requests over about 21 MB are refused before the body is read.
- **Jobs:** 5 attempts, a 60 s lease, backoff from 5 s doubling up to 10 min with full jitter, and a 2 s worker poll.

## Database roles and grants
| Role | Can do |
|---|---|
| quotation_owner | Migrations, seed, API-key creation and revocation, test-table truncation. FORCE RLS still applies to row access. |
| quotation_app (API) | SELECT tenants, memberships, pricing policies and alembic_version. SELECT/INSERT inbox_events, enquiries and attachments. INSERT jobs (cannot read them). SELECT only the API key whose ID it presents. **M4:** its own session row by hash (SELECT/INSERT, UPDATE revoked_at); quotations SELECT, UPDATE (status, current_version, updated_at); versions and decisions SELECT/INSERT; tasks SELECT, UPDATE (status, decided_at); enrollments SELECT/INSERT, UPDATE (consumed_at); bindings SELECT/INSERT, UPDATE (revoked_at); action references SELECT, UPDATE (consumed_at); own memberships and tenant names via `app.subject`. **M5:** quotation_documents SELECT; quotation_deliveries SELECT, UPDATE (first_downloaded_at). **M6:** quotation_responses SELECT/INSERT; quotations UPDATE (pricing_issues). |
| quotation_worker | SELECT/UPDATE/INSERT jobs for all tenants. SELECT inbox_events; SELECT/UPDATE enquiries and attachments; SELECT/INSERT/UPDATE workflow_runs, all only with the job's tenant context. Full access to the LangGraph checkpoint tables (no tenant column), opened only via workflow_runs. **M4:** SELECT tenants, memberships and pricing policies; quotations SELECT/INSERT, UPDATE (status, current_version, pricing_issues, updated_at); versions and tasks SELECT/INSERT; decisions and bindings SELECT; action references SELECT/INSERT, UPDATE (token, expiry, sent time). **M5:** quotation_documents SELECT/INSERT; quotation_deliveries SELECT/INSERT, UPDATE (status, document_id, provider_reference, last_error, updated_at, delivered_at). **M6:** quotation_responses SELECT/INSERT. Nothing else, and no access to sessions. |

All tenant tables use forced RLS on `app.tenant_id`, so without context nothing is visible.

## Health API contract
- `GET /health/live`: 200 with `{"status":"ok"}`, independent of PostgreSQL.
- `GET /health/ready`: 200 with `{"status":"ready"}`, or 503 with `{"status":"not_ready"}`.

Both are read-only and unauthenticated, and neither exposes tenant data. Readiness checks the migration head (`EXPECTED_REVISION`, currently `0005_approvals`) and rejects superuser, bypass-RLS and migration-owner connections. It is not a complete authorization audit.

## Enquiry API contract
`POST /api/v1/enquiries`, `GET /api/v1/enquiries/{id}` and (M5) `GET /api/v1/enquiries/{id}/quotation[.pdf]` require `Authorization: Bearer <API key>`; POST also requires `Idempotency-Key`. The quotation routes are described in [quotation delivery](../features/quotation-delivery.md#api); M6 adds `POST /api/v1/enquiries/{id}/quotation/response` ([customer acceptance](../features/customer-acceptance.md#api)). Status codes, the request shape and limits are in [enquiry intake](../features/enquiry-intake.md). The OpenAPI schema is served at `/docs`.

## Portal and channel API contract
There are cookie-session routes under `/api/v1/auth` and `/api/v1/tenants/{tenant_id}`, plus the signed `/api/v1/channels/simulated/events` webhook. See [quotation approval](../features/quotation-approval.md#api-portal-cookie-session). M5 adds the preview/approved PDF and delivery-status routes ([quotation delivery](../features/quotation-delivery.md#api)). M5 adds no new settings: PDFs are stored under `QUOTATION_STORAGE_DIR`. M6 adds the customer-view and withdrawal routes, and the per-business database setting `tenant_pricing_policies.quote_validity_days` (default 7; no environment variable).
