# Configuration reference
Implemented in [Settings](../../src/quotation_app/config.py). Explicit constructor values override environment variables, which override the root `.env`.

| Variable | Purpose |
|---|---|
| QUOTATION_DATABASE_URL | Required API runtime URL (`postgresql+psycopg`, explicit host and database) |
| QUOTATION_MIGRATION_DATABASE_URL | Owner URL, needed only for migrations, the seed and operator tasks (suspending a business); never used as a fallback |
| QUOTATION_WORKER_DATABASE_URL | Worker-role URL, needed only by `python -m quotation_app.worker`; never used as a fallback |
| QUOTATION_STORAGE_DIR | Attachment storage root (default `var/storage`, ignored by Git) |
| QUOTATION_MODEL | AI enquiry reader as `<provider>:<model>` (any LangChain chat model, e.g. `google_genai:gemini-3.5-flash-lite`). Unset = free offline rules, no AI (ADR 0017) |
| QUOTATION_MODEL_API_KEY | Secret API key for that provider; never commit it |
| QUOTATION_MODEL_OPTIONS | Optional JSON passed to the model as is, e.g. `{"timeout": 60, "max_retries": 2}` or `{"base_url": "..."}` |
| QUOTATION_DEV_LOGIN | Phase 2 (replaces `QUOTATION_AUTH_PROVIDER`). Email + password sign-in is always on; `true` also offers the development sign-in (pick a seeded demo person, no password). Unset = on in development/test, off in production; `true` in production is rejected |
| QUOTATION_DEMO_PASSWORD | Development/test only (rejected in production): the seed gives every demo person this password. Generated by `init_local_env.py --add-missing`; never commit it. Unset = demo people have no password (dev login only) |
| QUOTATION_DEFAULT_CATALOGUE_PROVIDER | Phase 3: the product source a new business starts with, an installed provider key with the catalogue purpose (default `local_catalogue`, "Our product list"). Empty = new businesses start without one. A key that is not an installed product source stops the API at start-up |
| QUOTATION_MAILER | Account email sender: an entry point name in `quotation_app.mailers` (default `console`, which writes files under `<storage dir>/dev-mail/`). `console` in production is rejected; a real sender comes in phase 5 |
| QUOTATION_MAILER_OPTIONS | Optional JSON passed to the mailer as is (no secrets: those go through the secret store) |
| QUOTATION_MAIL_FROM | Sender address of account emails. Default `no-reply@localhost.example`; required in production |
| QUOTATION_PUBLIC_PORTAL_URL | Portal address used in email links, ending in `/` (e.g. `https://quotes.example/portal/`). Default `http://localhost:8000/portal/`; https required in production |
| QUOTATION_TRUSTED_PROXY_COUNT | Reverse proxies in front of the API whose `X-Forwarded-For` is trusted for the client IP used by rate limits (default 0: the direct peer) |
| QUOTATION_PASSWORD_HASH_CONCURRENCY | Simultaneous Argon2id hashes, 64 MiB each (default 4, 1-16) |
| QUOTATION_SESSION_HOURS | Portal session lifetime (default 8, max 24) |
| QUOTATION_SESSION_COOKIE_SECURE | Force the Secure cookie flag locally (always on in production) |
| QUOTATION_SIMULATED_CHANNEL_SECRET | Development only (rejected in production). Signs events on the **deprecated** `/api/v1/channels/simulated/events` route (unset: that route answers 404), and the seed stores it as the demo phone connection's signing secret and derives its webhook token from it. Generated by init_local_env.py. Removed with the alias in phase 4/5 |
| QUOTATION_SECRET_STORE | Where provider secrets live (D8): an entry point name in `quotation_app.secret_stores`. Unset = `local` in development/test, `none` in production (until a cloud store is chosen, D24); `local` in production is rejected |
| QUOTATION_SECRET_STORE_KEY | Key of the `local` store: 32 bytes, url-safe base64. Generated by `init_local_env.py --add-missing`; never commit it. Losing it makes stored provider secrets unreadable |
| QUOTATION_SECRET_STORE_OPTIONS | Optional JSON passed to the secret store as is (for cloud stores later) |
| QUOTATION_PUBLIC_BASE_URL | Public address of this API (e.g. a tunnel in development), only used to show webhook URLs |
| QUOTATION_PORTAL_DIST_DIR | Built React portal (e.g. `portal/dist`), served at `/portal/`; unset means it is not served |
| QUOTATION_ENVIRONMENT | `development` (default), `test` or `production`. Production rejects demo seeding, demo passwords, the dev login, the simulated channel, the local secret store and the console mailer, and requires `QUOTATION_MAIL_FROM` and an https `QUOTATION_PUBLIC_PORTAL_URL` |
| POSTGRES_PASSWORD | Compose bootstrap superuser password |
| POSTGRES_OWNER_PASSWORD / POSTGRES_APP_PASSWORD / POSTGRES_WORKER_PASSWORD | Compose passwords for quotation_owner, quotation_app and quotation_worker |
| TEST_DATABASE_URL / TEST_MIGRATION_DATABASE_URL / TEST_WORKER_DATABASE_URL | Integration-test URLs; each must name a `*_test` database |

Database URL representations and validation messages hide secret inputs. Do not log unwrapped secrets, or rendered Compose configuration that contains passwords.

[.env.example](../../.env.example) contains placeholders. The [local setup generator](../../scripts/init_local_env.py) creates the ignored `.env`, and `--add-missing` appends settings that an older `.env` lacks.

Connect, statement and pool-wait timeouts are 3 seconds, with a pool of 5 and no overflow. These are development defaults, not measured production settings.

**Fixed limits (code constants, not settings):**
- **Intake:** text up to 20,000 characters, up to 5 attachments of 5 MiB each and 15 MiB in total; requests over about 21 MB are refused before the body is read.
- **Jobs:** 5 attempts, a 60 s lease, backoff from 5 s doubling up to 10 min with full jitter, and a 2 s worker poll.
- **Accounts (phase 2, user answers 2026-10-27):** passwords 12-128 characters; rate limits, link lifetimes and Argon2id parameters as in [accounts and onboarding](../features/accounts-and-onboarding.md#limits-and-timings). They are code constants on purpose, so installations cannot drift.

## Database roles and grants
| Role | Can do |
|---|---|
| quotation_owner | Migrations, seed, test-table truncation, suspending a business. Owns the four phase 2 `SECURITY DEFINER` functions. FORCE RLS still applies to row access. **Phase 3:** CREATE on its database (it owns `quotation_test`; `init.sql` grants it on `quotation_dev`) so migrations can create the trusted `pg_trgm` extension. A hosted database needs the same, or `pg_trgm` pre-installed (D24). |
| quotation_app (API) | SELECT tenants, memberships, pricing policies and alembic_version. SELECT/INSERT inbox_events, enquiries and attachments. INSERT jobs (cannot read them). SELECT only the API key whose ID it presents. **M4:** its own session row by hash (SELECT/INSERT, UPDATE revoked_at); quotations SELECT, UPDATE (status, current_version, updated_at); versions and decisions SELECT/INSERT; tasks SELECT, UPDATE (status, decided_at); enrollments SELECT/INSERT, UPDATE (consumed_at); bindings SELECT/INSERT, UPDATE (revoked_at); action references SELECT, UPDATE (consumed_at); own memberships and tenant names via `app.subject`. **M5:** quotation_documents SELECT; quotation_deliveries SELECT, UPDATE (first_downloaded_at). **M6:** quotation_responses SELECT/INSERT; quotations UPDATE (pricing_issues). **Phase 1 (0008):** connections and connection_events SELECT (plus one connection by ID for webhooks, `app.connection_id`); inbox_events UPDATE (processed_at, outcome). **Phase 2 (0010):** users through narrow policies only (`app.subject`, `app.user_email`, `app.user_id`, or members of the current business), INSERT (sign-up) and UPDATE (name, verified time); user_credentials of `app.user_id` only; email_verifications and password_resets by `app.user_id` or presented token hash; account_notices INSERT; invitations SELECT/INSERT, UPDATE (revoke, resend); admin_events SELECT/INSERT; tenants UPDATE (name, country, time zone, status, went_live_at, updated_at; a trigger allows only setting_up -> active); tenant_profiles SELECT, UPDATE; tenant_pricing_policies UPDATE (values, version); api_keys INSERT, UPDATE (revoked_at, revoked_by); connections INSERT, UPDATE (status); connection_events INSERT; rate_limit_counters; own sessions by `app.subject` (sign out everywhere); jobs INSERT without a business only for `send_account_email`; EXECUTE on `create_business`, `accept_invitation`, `change_member_roles`, `remove_member` (still no INSERT on tenants or memberships). **Phase 3 (0011):** the five catalogue tables SELECT/INSERT; UPDATE only on product and category columns (never on prices, stock or the change log, which a trigger also protects); DELETE on products (the service allows it only for unused ones). |
| quotation_worker | SELECT/UPDATE/INSERT jobs for all tenants. SELECT inbox_events; SELECT/UPDATE enquiries and attachments; SELECT/INSERT/UPDATE workflow_runs, all only with the job's tenant context. Full access to the LangGraph checkpoint tables (no tenant column), opened only via workflow_runs. **M4:** SELECT tenants, memberships and pricing policies; quotations SELECT/INSERT, UPDATE (status, current_version, pricing_issues, updated_at); versions and tasks SELECT/INSERT; decisions and bindings SELECT; action references SELECT/INSERT, UPDATE (token, expiry, sent time). **M5:** quotation_documents SELECT/INSERT; quotation_deliveries SELECT/INSERT, UPDATE (status, document_id, provider_reference, last_error, updated_at, delivered_at). **M6:** quotation_responses SELECT/INSERT. **Phase 1 (0008):** connections and connection_events SELECT; inbox_events INSERT, UPDATE (processed_at, outcome); enquiries INSERT; to route manager actions from the `process_inbound` job: approval_decisions and channel_bindings INSERT, approval_tasks UPDATE (status, decided_at), channel_enrollments SELECT, UPDATE (consumed_at), approval_action_refs UPDATE (consumed_at). **Phase 2 (0010):** tenant_profiles SELECT; one email row at a time by `app.account_ref_id` (email_verifications, password_resets, account_notices) and invitations in the job's business: SELECT, UPDATE (token hash, expiry, email status, sent time). Nothing else: no users, no credentials, no sessions. **Phase 3 (0011):** SELECT on catalogue categories, products, prices and stock (it never edits the catalogue). |

All tenant tables use forced RLS on `app.tenant_id`, so without context nothing is visible.

## Health API contract
- `GET /health/live`: 200 with `{"status":"ok"}`, independent of PostgreSQL.
- `GET /health/ready`: 200 with `{"status":"ready"}`, or 503 with `{"status":"not_ready"}`.

Both are read-only and unauthenticated, and neither exposes tenant data. Readiness checks the migration head (`EXPECTED_REVISION`, currently `0010_accounts`) and rejects superuser, bypass-RLS and migration-owner connections. It is not a complete authorization audit.

## Enquiry API contract
`POST /api/v1/enquiries`, `GET /api/v1/enquiries/{id}` and (M5) `GET /api/v1/enquiries/{id}/quotation[.pdf]` require `Authorization: Bearer <API key>`; POST also requires `Idempotency-Key`. The quotation routes are described in [quotation delivery](../features/quotation-delivery.md#api); M6 adds `POST /api/v1/enquiries/{id}/quotation/response` ([customer acceptance](../features/customer-acceptance.md#api)). Status codes, the request shape and limits are in [enquiry intake](../features/enquiry-intake.md). The OpenAPI schema is served at `/docs`.

## Portal and channel API contract
There are cookie-session routes under `/api/v1/auth`, `/api/v1/account`, `/api/v1/invitations`, `/api/v1/businesses` (phase 2, [accounts and onboarding](../features/accounts-and-onboarding.md#api)) and `/api/v1/tenants/{tenant_id}`, plus the signed `/api/v1/channels/simulated/events` webhook. See [quotation approval](../features/quotation-approval.md#api-portal-cookie-session). M5 adds the preview/approved PDF and delivery-status routes ([quotation delivery](../features/quotation-delivery.md#api)). M5 adds no new settings: PDFs are stored under `QUOTATION_STORAGE_DIR`. M6 adds the customer-view and withdrawal routes, and the per-business database setting `tenant_pricing_policies.quote_validity_days` (default 7; no environment variable). Phase 3 adds `/api/v1/tenants/{tenant_id}/catalogue/...` ([product catalogue](../features/product-catalogue.md#api-apiv1tenantstcatalogue-session--csrf)); the portal suggests a 7-day stock age for new businesses (Q10).
